# gm-framework v1 (легаси)

Распакованные исходники легаси-фреймворка, который раньше подключался
бинарником `lpm-libs/gm-framework-v1.1.1.phar`. Исходников этого фреймворка
за пределами phar не сохранилось, а править внутри бинарника нельзя —
поэтому он распакован в репозиторий и дальше поддерживается здесь.

Проект постепенно переезжает на `lpm-libs/framework/` (`GMFramework\*`);
новый код должен использовать её, а не эти классы.

## Как подключается

`lpm-core/init.inc.php` подключает только `GMFramework.class.php`, а дальше
`GMFramework::useFramework()` регистрирует `GMFramework::loadClass` как
автозагрузчик. `loadClass()` сопоставляет имя класса с подкаталогом по
`switch` и подключает `dirname(__FILE__) . <подкаталог> . <Класс>.class.php`.
Новый класс в этом каталоге не найдётся, пока он не добавлен в этот `switch`.

Часть файлов начинается с короткого тега `<?`, поэтому `short_open_tag = On`
обязателен (он и так требуется шаблонами проекта).

## Правки относительно phar

Изменены ровно четыре файла, остальные 50 совпадают с phar байт-в-байт.

- `db/DBConnect.class.php`:
  - фигурные индексы строки (`$s{0}`), снятые в PHP 8.0, заменены на `$s[0]`;
  - переопределениям методов `mysqli` добавлен `#[\ReturnTypeWillChange]` —
    без него PHP 8.1+ пишет по четыре предупреждения на каждый запрос;
  - `mysqli::query()` больше не получает `null` вторым аргументом;
  - режим отчётов mysqli возвращён к `MYSQLI_REPORT_OFF`: с PHP 8.1 драйвер
    по умолчанию бросает `mysqli_sql_exception`, а весь код вокруг построен
    на проверке результата запроса.
- `object/Cutdowner.class.php` — фигурный индекс строки.
- `object/StreamObject.class.php` — `getClientObject()` считает явный `null`
  отсутствием дополнительных полей: наследники передают свой аргумент как есть,
  и `func_get_args()` давала поле с именем `null`.
- `social/SocBilling.class.php` — `__get()` вызывал `parent::__get()` в классе
  без родителя, что с PHP 8.0 является ошибкой компиляции.
